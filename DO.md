- **Hotfix `/panel` — RSC serialization de iconos Lucide.** Diagnóstico de error en producción descubierto por el dev al publicar el primer alta como autónomo desde el wizard de onboarding: tras el redirect a `/panel`, la página se rompía con `Application error: a client-side exception` y `digest: 1621801304`. La consola revelaba el error de servidor enmascarado: `Functions cannot be passed directly to Client Components unless you explicitly expose it by marking it with "use server"` sobre un valor con shape `{$$typeof: ..., render: function, displayName: ...}` — la huella inequívoca de un `forwardRef` cruzando la frontera RSC. **Causa**: `src/components/features/provider-panel/PanelLayout/PanelLayout.tsx` era Server Component (sin `'use client'`); importaba 5 iconos de Lucide (`LayoutDashboard`, `CalendarDays`, `Scissors`, `Settings`, `Star`) y los almacenaba en un array `navItems: PanelNavItem[]` como **referencias al componente** (no como JSX). Después mapeaba ese array y renderizaba `<PanelLayoutLink item={item} ... />`, donde `PanelLayoutLink` sí era Client Component (`'use client'` en `PanelLayout.links.tsx`). En esa frontera, React Server Components intentaba serializar `item.icon` y se topaba con un `forwardRef` (objeto `{$$typeof, render, displayName}`) que no es serializable. **Por qué no se detectó antes**: el dev server (`next dev`) no aplica las mismas garantías de serialización RSC que el build de producción — el bug es invisible en local salvo que se haga `npm run build && npm start`. Por eso el wizard se cerró como "Capa 2 OK" hace dos días: nunca se llegó a un `/panel` real desde la build de Vercel, los tests E2E aún están pendientes de ejecutar, y el provider real del dev (que iba a disparar este path) era precisamente este alta de hoy. **lucide-react 1.16.0 no incluye `'use client'`** en los archivos de iconos individuales (sí en `Icon.mjs` / `DynamicIcon.mjs` / `context.mjs`), así que importar `LayoutDashboard` en un Server Component lo trae como `forwardRef` plano sin la marca de Client Reference que evitaría la serialización. Verificado leyendo `node_modules/lucide-react/dist/esm/`. **Fix**: añadir `'use client'` al `PanelLayout.tsx` (una línea + actualización del docstring). El árbol entero del shell del panel pasa a cliente; el coste en bundle es **cero** porque los iconos ya viajaban al navegador renderizados por `PanelLayoutLink`. La alternativa de "mover `navItems` al archivo cliente y dejar el shell server" era arquitectónicamente más pura pero implicaba mover también la iteración + `useTranslations` (que no puede cruzar como prop) — un refactor mayor para el mismo resultado funcional. La docstring actualizada explica la decisión y advierte del antipattern para futuros refactors. **Auditoría de patrones similares**: grep de `icon:\s*[A-Z]` en `src/` encontró 2 falsos positivos (`ForProvidersBenefits.tsx` + `CategoryGrid.tsx`) — ambos son Server Components que **renderizan el icono en su propio JSX** (no lo pasan como prop), patrón seguro. El único bug real estaba en `PanelLayout`. `typecheck` + `lint` + 436/436 tests verde. **Lección de proceso**: añadir `npm run build` al pre-flight antes de cerrar tareas que tocan la frontera Server/Client — `npm run validate` actual solo cubre `typecheck/lint/test`, y los tres pasan con bugs RSC dentro. **Pendiente de prevención**: cuando llegue cobertura E2E con build de producción contra Vercel preview, este tipo de regresión se cazaría antes de afectar al dev/cliente.
